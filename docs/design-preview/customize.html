定制

YAML 中的每个值都是 defaultAlgorithm 产出的默认值——浅色主题。Ant Design 主题化比替换 Design Token 更广：包含算法派生、组件级覆盖、动态切换、嵌套主题作用域、CSS 变量输出、静态 Token 消费，以及零运行时 CSS 提取。完整运行时 API 见 Customize Theme。

主题配置入口是 ConfigProvider 的 theme：

  1. Seed token 覆盖。传 theme.token 替换任意种子。主色和语义色种子会展开为派生阶梯；colorBgBase 与 colorTextBase 驱动中性表面和文字。间距、圆角、字号种子同理。
  2. 算法切换。设 theme.algorithm 换派生逻辑。defaultAlgorithm、darkAlgorithm、compactAlgorithm 可单独或组成数组使用——不要手工反色；算法会处理非线性的色板、表面、阴影和尺寸关系。
  3. 组件级覆盖。theme.components.Button（或任一组件 Token 命名空间）可覆盖单个组件的 Component Token 和所消费的 Alias Token，不影响其他组件。组件配置里的 algorithm 可让该覆盖仍跟随种子关系。
  4. 运行时作用域。改 ConfigProvider.theme 可动态切换；嵌套 ConfigProvider 创建局部主题，未改的 Token 从父级继承。静态 API（message.xxx、Modal.xxx、notification.xxx）不会自动拿到周围上下文；需要主题化静态反馈时，用 hook API、App 或显式 context holder。
  5. Token 消费与输出。React 内用 theme.useToken()，React 外用 theme.getDesignToken()。需要 CSS 变量时用 theme.cssVar；必须关闭运行时样式生成时用 theme.zeroRuntime 配合预构建或提取的 CSS。

自定义主题时，先保住 Ant Design 的交互结构、密度、状态反馈和组件语义，再改最小必要种子集：通常是 colorPrimary、状态色、borderRadius、fontFamily、fontSize 和中性表面基色。品牌页可以看起来不同，但表单、表格、导航、浮层、焦点态和校验反馈仍应像 Ant Design。避免生成绕过 Token、算法、theme.components、CSS 变量或提取静态样式的自定义 CSS；若主题无法通过这些官方层表达，应视为设计系统扩展，而不是页面一次性样式。
