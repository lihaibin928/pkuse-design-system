视觉对照 references/ant-design-v6.md（来源 ant.design/design.md）。组件何时使用见下方选用表，完整说明在 components/INDEX.md。第一版视觉基线是 Ant Design 默认蓝，不是绿色品牌皮肤。

概述

本文描述 Ant Design v6 默认浅色主题。系统遵循语义化版本：大版本（v5 → v6）表示设计语言重构，小版本与补丁版本保持本文稳定。主版本内的 Token 漂移见 CHANGELOG。

Ant Design 是蚂蚁集团用于交付企业软件的开源设计系统，主要面向中后台控制台、看板和运营工具。2015 年创建，目的是给大型产品团队一套有主张的共同基础，使密集、数据丰富的界面不必在每个屏幕上重新决定基础规则。

价值观

四个价值观指导系统中的每一个决策。

Natural

界面遵循既有惯例，不让回头用户感到意外。优先采用操作系统和前代企业软件中已存在的模式，而不是发明新交互。

Certain

用户始终知道自己处于什么状态、输入产生了什么结果、下一步是什么。悬停、焦点、加载和错误状态明确且一致。

Meaningful

视觉强调只留给行动。不传达信息的装饰一律去掉。

Growing

系统可以从小表单扩到密表格、再扩到多租户管理控制台，而不失去一致性。

色彩

色板由一个主色种子、四个语义状态种子（success / warning / error / info）以及文字与表面的中性色构成。种子经 @ant-design/colors 自动展开为背景浅色、悬停、按下和描边阶梯——改种子，整套派生色一起移动。

#1677FF 被选为主色，因为蓝色读起来可信、专注，既没有更深海军蓝的刻板，也没有高饱和青色的俏皮。它是操作、链接、焦点环、选中导航和激活 Tab 的默认品牌色。

无障碍说明：本文记录的是默认视觉 Token。部分品牌色组合（尤其是白字配 #1677FF，以及主文字配浅选中底）低于 WCAG AA 小字 4.5:1。若需严格无障碍，通过 ConfigProvider 加深 colorPrimary，或做组件级覆盖，不要发明一次性颜色。

运行时中性文字和叠层用 rgba(0, 0, 0, α)，而不是实心灰。原因是叠层：文字压在浅色卡片或彩色单元格上时，实心灰会切断底色，透明黑会自然混合。四级透明度：0.88 主文字、0.65 次文字、0.45 三级/描述、0.25 占位/禁用。文档中的 hex 是叠在白底上的等效结果，供静态导出；能走 alpha 的下游应优先用 @ant-design/cssinjs 的 rgba()。

字体

基础字号是 14px，不是 16。企业控制台用信息密度换取额外易读空间——1440px 宽窗口需要同时放下侧栏、顶栏、八列表格和详情。14px 正文在这些栏宽下接近约 75 字符的扫视甜点。

字体栈按系统 UI 字体优先：-apple-system、BlinkMacSystemFont、Segoe UI、Roboto、Helvetica Neue、Arial、Noto Sans。代码字体：SFMono-Regular、Consolas、Liberation Mono、Menlo、Courier。

产品界面只用两个字重：400（正文、控件、菜单项、Tab 标签）和 600（fontWeightStrong —— 标题、表头、任何 title 级文字）。细体（100–300）、粗体（700+）和斜体不用于界面骨架。斜体只允许出现在长文本文档里。选中/激活态的强调来自颜色和描边（边框、下划线），不是字重。

布局

所有间距对齐 4px 网格。六档间距（unit / xs / sm / md / lg / xl → 4 / 4 / 8 / 16 / 24 / 32）覆盖系统中每一个间隙、槽和内边距。Token 驱动的代码里不出现魔法数字。输入框水平 11px 内边距是网格确立前的历史值；一像素迁移会牵动海量已有屏幕，因此保留。

三层表面模型

永远不要在产品代码里写死 #FFF 或 #FAFAFA。读 Token。三层模型让暗色算法可以翻转表面阶梯而不拆布局。

1. bg-layout #F5F5F5 — 页面背景，包围并容纳其他一切。

2. bg-container #FFFFFF — 卡片、面板、表格、表单。大多数内容住在这里。

3. bg-elevated #FFFFFF

与 container 同 hex，靠阴影区分。用于对话框、下拉、气泡。

海拔与动效

Ant Design 是 flat-first。层级由边框和色调对比承担。阴影只出现在真正浮于上下文之上的表面。

阴影 Token 由 colorShadow 生成，同一名称可适应浅色/深色。核心档位：

Tertiary · boxShadowTertiary

轻抬起：0 1px 2px 0 rgba(0,0,0,0.05), 0 1px 6px -1px rgba(0,0,0,0.03), 0 2px 4px 0 rgba(0,0,0,0.03)

Popup · boxShadow / boxShadowSecondary

标准浮层：0 6px 16px 0 rgba(0,0,0,0.08), 0 3px 6px -4px rgba(0,0,0,0.12), 0 9px 28px 8px rgba(0,0,0,0.05)

  • Card（boxShadowCard）— 更紧的卡片抬起阴影，用于卡片需要与容器分离时。
  • Drawer / overflow（boxShadowDrawer*、boxShadowTabsOverflow*）— 贴边表面和滚动提示。
  • Popover arrow（boxShadowPopoverArrow）— 只用于 Tooltip / Popover 小三角。

动效

三种时长和一组 cubic-bezier，全部以 Token 暴露。不要任意挑选 transition-timing-function。需求对不上现有缓动时，用 motionEaseInOut 然后继续。

悬停色块查看 0.1s / 0.2s / 0.3s。缓动名称：motionEaseInOut、motionEaseOut、motionEaseIn、motionEaseOutBack、motionEaseOutCirc。

对与错

做

用四个设计价值观当平局裁决。两种做法冲突时，更能让用户状态确定、更易读的那个胜出。

从 colors.surface、surface-container、surface-layout 读表面。它们对应三层模型。

找不到更具体 Token 时，组件级过渡用 motionDurationMid（0.2s）。

预设色板（blue 到 lime）只留给标签、图表和分类可视化。

每一个间隙、内边距和槽都通过间距刻度对齐 4px 网格。

不做

同一表面不要叠两个主色按钮。只留一个，其余降为 default。

不要硬编码 #FFFFFF 或 #FAFAFA。hex 是附带结果，角色才重要。

不要发明自定义 cubic-bezier。用已命名缓动。

不要在预设色板外铸造强调色给一次性 UI。若某屏看起来需要，多半该改布局。

不要在产品代码里用魔法数字。刻度缺一档时，该重看设计，而不是一像素覆盖。

PKUSE 叠加：不要用 #12372a / #176b4d 做顶栏或品牌块，也不要把页面底改成 #f2f5f2 这类绿灰。成功绿只出现在 Tag、Alert、状态点。

定制

YAML 中的每个值都是 defaultAlgorithm 产出的默认值——浅色主题。Ant Design 主题化比替换 Design Token 更广：包含算法派生、组件级覆盖、动态切换、嵌套主题作用域、CSS 变量输出、静态 Token 消费，以及零运行时 CSS 提取。完整运行时 API 见 Customize Theme。

主题配置入口是 ConfigProvider 的 theme：

  1. Seed token 覆盖。传 theme.token 替换任意种子。主色和语义色种子会展开为派生阶梯；colorBgBase 与 colorTextBase 驱动中性表面和文字。间距、圆角、字号种子同理。
  2. 算法切换。设 theme.algorithm 换派生逻辑。defaultAlgorithm、darkAlgorithm、compactAlgorithm 可单独或组成数组使用——不要手工反色；算法会处理非线性的色板、表面、阴影和尺寸关系。
  3. 组件级覆盖。theme.components.Button（或任一组件 Token 命名空间）可覆盖单个组件的 Component Token 和所消费的 Alias Token，不影响其他组件。组件配置里的 algorithm 可让该覆盖仍跟随种子关系。
  4. 运行时作用域。改 ConfigProvider.theme 可动态切换；嵌套 ConfigProvider 创建局部主题，未改的 Token 从父级继承。静态 API（message.xxx、Modal.xxx、notification.xxx）不会自动拿到周围上下文；需要主题化静态反馈时，用 hook API、App 或显式 context holder。
  5. Token 消费与输出。React 内用 theme.useToken()，React 外用 theme.getDesignToken()。需要 CSS 变量时用 theme.cssVar；必须关闭运行时样式生成时用 theme.zeroRuntime 配合预构建或提取的 CSS。

自定义主题时，先保住 Ant Design 的交互结构、密度、状态反馈和组件语义，再改最小必要种子集：通常是 colorPrimary、状态色、borderRadius、fontFamily、fontSize 和中性表面基色。品牌页可以看起来不同，但表单、表格、导航、浮层、焦点态和校验反馈仍应像 Ant Design。避免生成绕过 Token、算法、theme.components、CSS 变量或提取静态样式的自定义 CSS；若主题无法通过这些官方层表达，应视为设计系统扩展，而不是页面一次性样式。

PKUSE 第一版：不改品牌种子。生成应用通过 ConfigProvider 锁定默认主色 #1677FF，并用应用级 prefixCls 与 CSS Variable key。
